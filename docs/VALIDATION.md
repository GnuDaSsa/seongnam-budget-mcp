## 2026-11-10 정답셋 평가와 총액·비교·일치 신뢰도 개선 (서버 0.4.0, 조회 정책 2026-11-10.6)

이번 변경은 로컬 빌드에서만 검사했다. 운영 서버는 아직 0.3.0이며 이 절의 "변경 후" 수치는 운영 반영 결과가 아니다.

### 정답셋

`tests/fixtures/golden-queries.json`에 64개 질의를 11개 유형으로 두었다. 정답셋은 모델이 초안을 만들고 수록 원문으로 대조한 것이며 사람이 검수한 정답이 아니다. 각 질의는 반환 근거가 연도·편성 구분·부서·원문 포함 문구 등 조건을 만족하는지로 판정한다. `npm run evaluate`는 로컬 빌드를 직접 호출하고, `node scripts/evaluate-golden.mjs --base <URL>`은 원격 서버를 호출한다.

### 변경 내용

- 총액 질문: 모든 연도에서 해당 연도 본예산 "세입·세출예산규모 및 총괄표" 1쪽을 직접 읽는다. 이전에는 2026년만 직접 조회했고 다른 연도는 일반 검색으로 넘어가 결산서가 반환되었다. 단위와 합계(일반회계 + 특별회계)가 대조되면 `answer_card`(`retrieval.mode: verified_total_table`)를 반환한다. 대조되지 않으면 원문만 반환한다(`total_table_unverified`, 예: 2009년). 표 숫자가 추출되지 않은 구형 HWP(2007·2008년)는 본예산으로 한정한 일반 검색으로 처리한다. 부서나 주제를 명시한 질문은 총액 질문으로 보지 않는다.
- 연도 비교: 편성 구분을 밝히지 않은 세출 사업 비교는 연도별 본예산으로 맞춘다(`query_interpretation.comparison_budget_basis: main_budget_default`, 안내문 추가). 질문에 추경·결산 등을 명시하면 그대로 따른다. 이전에는 연도마다 본예산과 추경이 섞여 반환되었다.
- 비교 응답 중복 제거: 근거 본문을 최상위 `evidence`에 한 번만 싣고 `per_year[]`에는 `evidence_ids`만 둔다. `per_year[].evidence`를 읽던 클라이언트는 최상위 `evidence`를 사용해야 한다.
- 조사가 붙은 연도 표현: "2024년과", "2025년의", "2020년부터"에서 연도가 검색어에 남아 키워드 검색이 실패하던 문제를 고쳤다(`worker/retrieval-phrases.js`).
- 일치 신뢰도 `match_quality.level`: verified / keyword / semantic_bridge / semantic_only / none. `semantic_only`이면 근거 본문을 일치 구간 주변 최대 1,200자로 줄이고 사업 경로 목록을 생략하며, 같은 사업으로 단정하지 말라는 `next_action`을 반환한다. 서버 지침(SERVER_RULES)에도 같은 내용을 추가했다.
- 의미 질의의 세출명세서 연결(`semantic_bridge`): 질의어가 원문에 없고 의미 유사 후보가 성인지예산서 등 설명형 자료일 때, 그 자료의 사업명 머리("사업명(회계) □사업개요")를 읽어 같은 연도 세출명세서를 키워드로 다시 찾는다. 사업명이 실제로 있는 세출명세서 근거만 `bridge`(business_name, from_id)와 함께 반환한다. 유사도 기준은 경험적으로 정했다(token MaxSim 0.6 이상, 또는 cosine 0.48 이상이면서 MaxSim 0.55 이상). 질문과 사업의 대응은 추정이며 응답에 그렇게 표시한다.
- 깨진 인코딩 거부: UTF-8이 아닌 MCP 요청 본문은 HTTP 400 / JSON-RPC -32700으로, 대체 문자(U+FFFD)가 든 검색어는 오류로 처리한다. 이전에는 깨진 검색어로 검색해 무관한 근거를 반환했다.
- 드문 토큰 가중치 캐시: 별도 정적 사이트에서 읽는 드문 토큰 가중치를 요청 사이에 재사용한다(상한 8,192개).
- 분석 요청어 제외: "지출", "지출액", "비율", "비중", "시도비", "국도비", "현황", "추이", "증감", "변화", "분담", "구성", "얼마나"와 순위·크기 요청어("가장", "제일", "비싼", "큰", "많은", "최대", "상위", "순위", "포함" 등)는 조사를 뗀 형태까지 필수 검색어에서 뺀다(`worker/retrieval-phrases.js`). "2024년 공공근로 지출과 시도비 비율"처럼 물으면 이 단어들이 원문 사업 행에 없어 키워드 검색이 0건이 되고 무관한 쪽이 반환되었다(운영 0.3.0에서 재현, 정답셋 `analytic_wording` 유형 4개로 추가).
- "추경 포함" 해석: "추경 포함", "추경까지", "추경도", "합쳐", "더해"는 본예산과 추경을 함께 조회한다. 이전에는 추경만으로 해석해 본예산을 후보에서 뺐다. "추경 반영"은 기존대로 추경만 조회한다.
- 부서 개요 `department_overview`: 부서를 하나 명시하고 연도가 하나인 세출 질문에서, 그 연도의 본예산과 수록된 추경 회차 중 원문 부서 머리말이 확인된 쪽을 모두 읽는다(상한 80쪽, 같은 편성이 전체본과 부서별 PDF로 중복 수록되면 쪽이 많은 문서 하나). 편성별로 `department_total`(원문 부서 합계 행), `businesses`(세부사업 금액 내림차순 상위 15)를 반환하고, `latest_amounts`(본예산 금액에 수록된 추경 회차의 예산액을 순서대로 반영한 계산값, `as_of`에 편성 표시)와 `largest_business`를 함께 반환한다. 한계: 추경 명세서에는 변경된 사업만 나오고, 수록되지 않은 회차·스캔 쪽은 반영되지 않으며, 들여쓰기 구조가 다른 과거 서식은 읽지 못할 수 있다. 서로 다른 편성의 금액은 합산하지 않는다. 서버 지침과 `budget_research` 도구 설명에도 반영했다.
- 결산 근거 제한: 결산을 묻지 않은 질문에는 시 결산서를 근거로 반환하지 않는다(아래 "예산편성 우선").
- 부서 묶음 `business_rollup`: 근거가 verified이고 부서·주제·기관을 명시하지 않은 세출 사업 질문에서, 같은 편성(편성 구분 미지정 시 본예산) 안에 같은 세부사업명 행이 있는 부서를 키워드로 다시 모아 `rows[]`(부서, 예산액, 전년도 또는 기정액, 증감, 열 대응 확인 여부, 쪽 위치)로 반환한다. 전체본과 부서별 PDF의 같은 행은 한 번만 센다. 모든 행에서 "예산액 − 비교액 = 증감"이 맞고 단위가 같고 후보가 상한(40쪽)에 닿지 않았을 때만 `calculated_total`(계산값)을 제공한다. 본예산과 추경은 합산하지 않는다. 한계: 세부사업명이 부서마다 다르게 표기되면 묶이지 않고, 행 일치는 사업명 완전 일치(공백 무시) 기준이다.
- 긴 기간 조회: 한 번에 최대 8개 연도(`POLICY.max_series_years`). 3개 연도까지는 기존처럼 근거 본문을, 4~8개 연도는 연도별 사업 행 주변 최대 1,500자로 간추려 반환하고 안내문을 붙인다. 9개 이상은 오류다. 이전에는 최대 3년이었다. 서버 지침과 `budget_research` 도구 설명에도 반영했다.- 버전 문자열은 `worker/policy.js`의 `VERSION` 한 곳에서 관리한다.

### CI

GitHub Actions의 코퍼스 검사(스냅샷 내려받기, 빌드, 전체 테스트, 정답셋 평가)를 수동 실행 외에 main 반영과 주 1회 일정에서도 실행한다. 전체 테스트는 배포 절차(`scripts/release.mjs prepare`)에서 실행한다. 이후 변경을 포함한 로컬 빌드의 전체 테스트는 배포 절차에서 실행하며 정답셋은 58/64다. 산하기관 검색 자산이 바뀌었으므로 공개 사이트에 게시되기 전까지 GitHub Actions의 코퍼스 검사는 스냅샷 대조에서 실패한다.

### 산하기관 수집 규칙과 수록 결과

법령이 인터넷 홈페이지 공시를 의무로 정한 산하기관 자료는 robots 제한 경로에서도 수집하도록 규칙을 바꿨다(`pipeline/affiliate-sources.json`의 자료별 `legal_basis`가 `DISCLOSURE_BASES`로 시작할 때만, 제한 경로 요청은 3초 간격). 근거가 확인되지 않은 자료, 검색·관리 기능 경로, 지방의회 회의록 부록은 계속 수집하지 않으며 OCR은 사용하지 않는다. 수록 문서마다 `legal_basis`와 `robots_disallowed`를 카탈로그에 기록한다. 조문 근거와 구현은 `docs/AFFILIATES.md`에 있다. 수집기 회귀 검사 `pipeline/test_affiliates.py` 10개가 통과했다.

`snapshot/affiliates/catalog.json` 집계(로컬 빌드, 운영 미게시):

| 수록 기관 | 4개 | 7개 |
| 수록 문서 | 10건 | 25건 |
| 수록 페이지 | 160쪽 | 515쪽 |

새 규칙으로 robots 제한 경로 또는 robots.txt 오류 상태에서 수집한 수록 문서는 5건이다(성남산업진흥원 4, 성남시장학회 1). 성남문화재단 4건은 내려받기 주소가 제한 경로가 아니었다. 성남도시개발공사의 2025·2026 본예산 XLSX는 게시와 공시 근거를 확인했으나 서버가 응답 본문을 중간에 끊어 완결 파일을 얻지 못했고, XLSX가 현재 수집기 대상 형식이 아니어서 수록하지 못했다. 성남시복지재단은 경영공시의 예산·결산 분류에 게시물이 없고 성남시정연구원은 신규 자료가 없다. 시 재정공시는 근거가 있으나 시 자료에 넣으면 전체 벡터 색인을 다시 만들어야 하고 배포 용량 한도에 가까워 이번에는 수집하지 않았다. 기관별 수록 내용은 `docs/AFFILIATES.md` 표와 같다.

### 예산편성 우선

시 결산서는 질문이나 인자로 결산·집행액을 명시했을 때만 근거가 된다(`worker/policy.js`의 `sourceAllowed`). 이전에는 결산을 묻지 않은 "2024년 청년 지원 사업 예산"에 결산서 근거가 본예산과 섞여 반환되었다. 기관을 명시한 질문에서는 기관 결산서가 유일한 세부 자료인 경우가 있어 기존처럼 결산서도 반환한다. 회귀 테스트 `tests/budget-priority.test.mjs`를 추가했다.

- 장기 운영 부하 시험, 사람 정답셋 기반 정확도 평가는 아직 수행하지 않았다. 정적 토큰 리랭커를 cross-encoder 모델로 표현하지 않는다.

## 2026-11-08 MCP 중심 연동 보완

서비스 역할은 RAG 검색과 원문 근거 반환이다. 생성 답변은 연결된 GPT가 수행한다. 서버에 Luna 답변·LLM 리랭킹·모델 API 키 의존성을 추가하지 않는다. 공개 /public-mcp의 익명 접근을 유지한다.

기본 진입점은 budget_research: 검색·리랭킹 후 최대 4개의 원문 근거, 위치, 단위, 출처, 수집 한계를 함께 반환한다. 각 근거는 최대 6,000 Unicode 문자이며 잘림과 원문 구간을 명시한다. 이미 충분한 근거를 받은 GPT는 같은 검색·상태·전문 조회를 반복할 필요가 없다. 비교 질문은 연도별로 조회하고 편성 구분을 맞춘다.

ChatGPT 리서치 호환 search(query) → fetch(id)를 추가했다. id/title/url 및 전문·metadata, 출력 JSON Schema를 제공한다. 기존 도구 5개도 유지하여 총 8개 읽기 전용 도구를 노출한다. GPTs Actions 호환 /openapi.json은 같은 /api/research, /api/page, /api/status를 기술한다. 상세 연결은 MCP_CONNECT.md를 따른다.

성능 변경: 동일 샤드의 페이지·본문을 묶어 읽고, 전체 키워드 후보 순위에 필요한 문서 인덱스·문자 수·단위 여부·정확한 중복 식별자를 rank.bin.gz에 저장한다. 112,386개 위치의 누락과 catalog SHA-256을 검증한다. build.mjs가 매 빌드에 이 자산을 재생성한다. 검색 결과 캐시는 인스턴스 메모리에서 5분/12건/약 2MB로 제한하며 필터별로 분리한다. vector/lexical/hydrate/rerank 단계 시간을 반환한다. 원문·임베딩·점수 공식은 변경하지 않았다.

검증: Node 21개 검사(기존 의미 모델 3개 + Worker 18개), 공식 MCP SDK 1.32.2의 Streamable HTTP 무인증 연결, 4개 기준 질의의 상위 5개 ID·순위·점수·청크 경계 동일성, 인용 본문 구간의 원문 일치, search/fetch 출력 스키마, 캐시 필터 분리. 로컬 기준선의 자산 읽기는 80→49, 72→36, 215→102, 64→38회. 로컬 처리 시간은 시스템 부하에 따라 변하며 실서버 기록과 구분한다. 별도 모델 API 호출을 하지 않았다.

남은 범위: 미추출 PDF·구형 HWP와 부서별 산발 자료, 자동 동기화, 독립된 사람 정답셋 기반 정확도 평가, 장기 부하 검증. 공개 MCP 배포가 ChatGPT 공개 플러그인 디렉터리의 심사·게시 완료를 의미하지 않는다.
