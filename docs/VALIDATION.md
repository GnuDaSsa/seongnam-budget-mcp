# 검증 기록

## 2026-11-10 정답셋 평가와 총액·비교·일치 신뢰도 개선 (서버 0.4.0, 조회 정책 2026-11-10.6)

이번 변경은 로컬 빌드에서만 검사했다. 운영 서버는 아직 0.3.0이며 이 절의 "변경 후" 수치는 운영 반영 결과가 아니다.

### 정답셋

`tests/fixtures/golden-queries.json`에 60개 질의를 10개 유형으로 두었다. 정답셋은 모델이 초안을 만들고 수록 원문으로 대조한 것이며 사람이 검수한 정답이 아니다. 각 질의는 반환 근거가 연도·편성 구분·부서·원문 포함 문구 등 조건을 만족하는지로 판정한다. `npm run evaluate`는 로컬 빌드를 직접 호출하고, `node scripts/evaluate-golden.mjs --base <URL>`은 원격 서버를 호출한다.

변경 전 수치는 운영 서버에 같은 평가기를 한 번 실행한 결과이고, 변경 후 수치는 로컬 빌드 결과다. 두 환경의 응답 시간은 비교하지 않았다. 정답셋이 이번 변경의 실패 사례를 보고 만들어졌으므로 total·comparison·absent의 향상 폭은 일반 질문 전체의 정확도가 아니라 알려진 문제의 수정 여부를 나타낸다.

### 변경 내용

- 총액 질문: 모든 연도에서 해당 연도 본예산 "세입·세출예산규모 및 총괄표" 1쪽을 직접 읽는다. 이전에는 2026년만 직접 조회했고 다른 연도는 일반 검색으로 넘어가 결산서가 반환되었다. 단위와 합계(일반회계 + 특별회계)가 대조되면 `answer_card`(`retrieval.mode: verified_total_table`)를 반환한다. 대조되지 않으면 원문만 반환한다(`total_table_unverified`, 예: 2009년). 표 숫자가 추출되지 않은 구형 HWP(2007·2008년)는 본예산으로 한정한 일반 검색으로 처리한다. 부서나 주제를 명시한 질문은 총액 질문으로 보지 않는다.
- 연도 비교: 편성 구분을 밝히지 않은 세출 사업 비교는 연도별 본예산으로 맞춘다(`query_interpretation.comparison_budget_basis: main_budget_default`, 안내문 추가). 질문에 추경·결산 등을 명시하면 그대로 따른다. 이전에는 연도마다 본예산과 추경이 섞여 반환되었다.
- 비교 응답 중복 제거: 근거 본문을 최상위 `evidence`에 한 번만 싣고 `per_year[]`에는 `evidence_ids`만 둔다. `per_year[].evidence`를 읽던 클라이언트는 최상위 `evidence`를 사용해야 한다.
- 조사가 붙은 연도 표현: "2024년과", "2025년의", "2020년부터"에서 연도가 검색어에 남아 키워드 검색이 실패하던 문제를 고쳤다(`worker/retrieval-phrases.js`).
- 일치 신뢰도 `match_quality.level`: verified / keyword / semantic_bridge / semantic_only / none. `semantic_only`이면 근거 본문을 일치 구간 주변 최대 1,200자로 줄이고 사업 경로 목록을 생략하며, 같은 사업으로 단정하지 말라는 `next_action`을 반환한다. 서버 지침(SERVER_RULES)에도 같은 내용을 추가했다.
- 의미 질의의 세출명세서 연결(`semantic_bridge`): 질의어가 원문에 없고 의미 유사 후보가 성인지예산서 등 설명형 자료일 때, 그 자료의 사업명 머리("사업명(회계) □사업개요")를 읽어 같은 연도 세출명세서를 키워드로 다시 찾는다. 사업명이 실제로 있는 세출명세서 근거만 `bridge`(business_name, from_id)와 함께 반환한다. 유사도 기준은 경험적으로 정했다(token MaxSim 0.6 이상, 또는 cosine 0.48 이상이면서 MaxSim 0.55 이상). 질문과 사업의 대응은 추정이며 응답에 그렇게 표시한다.
- 깨진 인코딩 거부: UTF-8이 아닌 MCP 요청 본문은 HTTP 400 / JSON-RPC -32700으로, 대체 문자(U+FFFD)가 든 검색어는 오류로 처리한다. 이전에는 깨진 검색어로 검색해 무관한 근거를 반환했다.
- 드문 토큰 가중치 캐시: 별도 정적 사이트에서 읽는 드문 토큰 가중치를 요청 사이에 재사용한다(상한 8,192개).
- 버전 문자열은 `worker/policy.js`의 `VERSION` 한 곳에서 관리한다.

## 2026-11-09 정확한 예산 항목 검색 수정

2025년도 자본적위탁사업비 질의는 원문과 키워드 색인에 해당 항목이 있는데도 혼합 검색 상위 4개가 모두 관련 없는 문서였다. 연도 접미어가 검색어로 남고, 정확한 용어가 없는 구간을 의미 리랭킹하는 문제를 확인했다.

연도 필터는 보존하면서 검색어에서 완전한 연도 표현을 분리했다. 원문 공백을 정규화한 연속 문구가 확인되고 나머지 조건도 제한된 문맥 또는 문서 제목에서 확인되는 후보를 우선한다. 해당 문구의 실제 위치를 원문 코드포인트에 대응시켜 검증한 구간을 반환한다. 숫자 코드 질의는 정확 일치 우선순위로 임의 해석하지 않으며, 벡터 전용 검색 경로는 유지한다.

로컬 실제 스냅샷 검사에서 해당 질의의 상위 4개 원문 일치가 0/4에서 4/4로 바뀌었다. 띄어쓰기·정식 명칭·2025년 본예산·주택과 필터, Unicode 위치, 흩어진 두 글자에 의한 오탐, 검증 문맥과 반환 구간의 동일성을 검사했다. `npm run test:unit` 10개, 빌드, `node --use-system-ca --test tests/*.test.mjs` 34개가 통과했다. 시스템 인증서 사용은 해당 Node 프로세스에만 적용했다.

기존 검색 기준선 파일은 보존했다. 정확 문구가 있는 질의의 순위는 의도적으로 바뀌므로 원문 일치와 구간·필터 정확성을 검사하고, 정확 문구가 없는 의미 검색은 기존 순위 회귀검사를 유지한다. 이 결과는 전체 질문의 정확도나 일반 ChatGPT의 자동 도구 선택 검증 완료를 뜻하지 않는다.

## 배포 후 발견한 오류와 수정

2026년 페이지의 단위사업 제목이 금액 단위로 표시되는 문제를 찾아 61,236개 위치의 단위 정보를 재검사했다. 원/천원/백만원/억원만 추출하며 복수 단위는 함께 표시한다. 원문 텍스트는 바꾸지 않았다.

구형 HTML 표에서 앞선 성인지예산 섹션명이 뒤 추경 문서 제목에 남는 문제도 수정했다. 실제 목록의 114개 제목을 다시 생성했으며 본문·금액·회계연도는 바꾸지 않았다.

- 장기 운영 부하 시험, 사람 정답셋 기반 정확도 평가는 아직 수행하지 않았다. 정적 토큰 리랭커를 cross-encoder 모델로 표현하지 않는다.

## 2026-11-08 MCP 중심 연동 보완

서비스 역할은 RAG 검색과 원문 근거 반환이다. 생성 답변은 연결된 GPT가 수행한다. 서버에 Luna 답변·LLM 리랭킹·모델 API 키 의존성을 추가하지 않는다. 공개 /public-mcp의 익명 접근을 유지한다.

기본 진입점은 budget_research: 검색·리랭킹 후 최대 4개의 원문 근거, 위치, 단위, 출처, 수집 한계를 함께 반환한다. 각 근거는 최대 6,000 Unicode 문자이며 잘림과 원문 구간을 명시한다. 이미 충분한 근거를 받은 GPT는 같은 검색·상태·전문 조회를 반복할 필요가 없다. 비교 질문은 연도별로 조회하고 편성 구분을 맞춘다.

ChatGPT 리서치 호환 search(query) → fetch(id)를 추가했다. id/title/url 및 전문·metadata, 출력 JSON Schema를 제공한다. 기존 도구 5개도 유지하여 총 8개 읽기 전용 도구를 노출한다. GPTs Actions 호환 /openapi.json은 같은 /api/research, /api/page, /api/status를 기술한다. 상세 연결은 MCP_CONNECT.md를 따른다.

성능 변경: 동일 샤드의 페이지·본문을 묶어 읽고, 전체 키워드 후보 순위에 필요한 문서 인덱스·문자 수·단위 여부·정확한 중복 식별자를 rank.bin.gz에 저장한다. 112,386개 위치의 누락과 catalog SHA-256을 검증한다. build.mjs가 매 빌드에 이 자산을 재생성한다. 검색 결과 캐시는 인스턴스 메모리에서 5분/12건/약 2MB로 제한하며 필터별로 분리한다. vector/lexical/hydrate/rerank 단계 시간을 반환한다. 원문·임베딩·점수 공식은 변경하지 않았다.

검증: Node 21개 검사(기존 의미 모델 3개 + Worker 18개), 공식 MCP SDK 1.32.2의 Streamable HTTP 무인증 연결, 4개 기준 질의의 상위 5개 ID·순위·점수·청크 경계 동일성, 인용 본문 구간의 원문 일치, search/fetch 출력 스키마, 캐시 필터 분리. 로컬 기준선의 자산 읽기는 80→49, 72→36, 215→102, 64→38회. 로컬 처리 시간은 시스템 부하에 따라 변하며 실서버 기록과 구분한다. 별도 모델 API 호출을 하지 않았다.

남은 범위: 미추출 PDF·구형 HWP와 부서별 산발 자료, 자동 동기화, 독립된 사람 정답셋 기반 정확도 평가, 장기 부하 검증. 공개 MCP 배포가 ChatGPT 공개 플러그인 디렉터리의 심사·게시 완료를 의미하지 않는다.
