# 조회·답변 규칙

정책 버전: 2026-11-12.3. 실행 원본: `worker/policy.js`.

| 질문 상황 | 적용 규칙 |
|---|---|
| 연도 미지정 | 2026년 검색. 답변에 “2026년 기준” 명시 |
| 연도 명시 | 해당 연도 우선. 다른 연도로 조용히 대체하지 않음 |
| 질문 연도와 `year` 인자 불일치 | 질문에 적힌 연도·범위·전체 연도 표현을 적용하고 `query_interpretation.conflicts`에 `field: year`로 기록. 인자와 질문이 같은 해이면 충돌 아님. 여러 연도 질문을 `search_budget`으로 보내면 오류로 안내 |
| 전체·역대 연도 | `year_scope=all`. ‘모든 예산’만 말하면 기본 연도 유지 |
| 올해·작년·내년 | 정책 기준 2026년과 그 전년·다음 해(`year_basis: relative`). "작년과 올해"처럼 둘을 함께 말하면 두 연도 비교. 실제 자료 유무 별도 확인 |
| 전년도 대비·작년 대비·작년보다 | 비교 기준이므로 조회 연도를 바꾸지 않음. 원문의 전년도예산액·비교증감 열로 답하도록 안내문 추가 |
| 여러 연도 비교·긴 기간 조회 | 서버가 연도별 검색을 수행. 한 번에 최대 8개 연도(`max_series_years`), 9개 이상은 오류. 3개 연도까지는 근거 본문, 4~8개 연도는 연도별 사업 행 주변 최대 1,500자로 간추려 반환하고 안내문 추가. 동일 문서·회계·사업 범위만 비교. 편성 구분을 밝히지 않은 세출 사업 비교는 연도별 본예산으로 맞춤(`comparison_budget_basis: main_budget_default`). 추경·결산을 명시하면 그대로 따름. 근거 본문은 최상위 `evidence`에 한 번만 있고 `per_year[]`는 `evidence_ids`만 가짐 |
| 총예산만 질문 | 해당 연도(미지정 시 2026년) 본예산 "세입·세출예산규모 및 총괄표" 1쪽을 직접 조회. 총액=일반+특별과 단위가 대조되면 `answer_card`(`verified_total_table`). 대조되지 않으면 원문만 반환(`total_table_unverified`). 표 숫자가 추출되지 않은 구형 HWP(2007·2008년)는 본예산으로 한정한 일반 검색. 부서·주제를 명시한 질문은 총액 질문으로 보지 않음. "얼마나 되나요", "총금액을 알려주세요" 같은 말끝·표현도 같은 경로. 추경·결산을 명시하면 총괄표 직접 조회를 하지 않음 |
| 예산과(부서)와 "예산+과" | 질문 첫머리(연도·성남시 뒤 포함)의 `예산과 총예산·총액·전체·기본경비`(`예산과와·예산과랑·예산과 및 총예산`처럼 조사·접속어가 붙은 형태 포함), `조정실 예산과`, `예산과에서·예산과가`, `예산과 소관·담당`은 부서 예산과로 인식. `사업 예산과 통계목`처럼 사업명 뒤에 오면 접속 표현으로 보고 부서로 인식하지 않으며 필수 검색어에서도 제외. 독립된 낱말 `예산과`(조사 `와·랑·이랑·하고` 포함)가 있으면 부서 인식 여부와 무관하게 시 전체 총액 직접 조회를 하지 않음 |
| 편성목·통계목·세부사업 질문 | 문서 종류가 없으면 본예산 사업명세서를 우선 |
| 본예산·추경·결산 명시 | 필터 적용. 두 종류를 동시에 물으면 출처별 구분 |
| 최신 추경 | 수록된 해당 연도의 최종 회차. 완전한 최신 수집을 보장한다고 표현하지 않음 |
| 근거 충분 | 한 번의 `budget_research`로 답변. 상태 조회와 같은 뜻의 재검색 생략 |
| 근거 부족 | 표현을 좁힌 재검색 1회 또는 원문 조회. 없으면 확인 불가 |
| 일치 신뢰도 | `match_quality.level`: verified / keyword / semantic_bridge / semantic_only / none. `semantic_only`이면 근거 본문을 일치 구간 주변 최대 1,200자로 줄이고 사업 경로 목록을 생략하며 같은 사업으로 단정하지 않음. `semantic_bridge`의 질문↔사업 대응은 추정이며 `bridge`(business_name, from_id)로 연결 근거를 표시 |
| 깨진 인코딩 | UTF-8이 아닌 요청 본문은 HTTP 400 / JSON-RPC -32700. 대체 문자(U+FFFD)가 든 검색어는 오류 |
| 여러 부서에 나뉜 사업 | 근거가 verified이고 부서·주제·기관을 명시하지 않은 세출 사업 질문에서 같은 편성 안의 같은 세부사업명(공백 무시 완전 일치) 행을 부서별로 모아 `business_rollup.rows[]`로 반환. 모든 행의 예산액 − 비교액 = 증감, 단위 동일, 후보가 상한(40쪽)에 닿지 않을 때만 `calculated_total`(계산값). 본예산과 추경은 합산하지 않음. 세부사업명이 부서마다 다르면 묶이지 않음 |
| 끝의 출력 요청 | 질문 끝의 `원문 페이지와 함께 알려주세요`류 요청 절과 조사가 붙은 편성·출력 항목(`통계목을`, `예산을`, `편성목과`)은 필수 검색어에서 제외. 그 앞 사업명의 소유격(`지원사업의`)만 뗌. 제외·집행·이월·잔액·항목 코드와 질문 중간의 낱말은 유지 |
| 분석·순위 요청어 | 지출·비율·비중·시도비·국도비·현황·추이·증감·변화·분담·구성과 가장·제일·비싼·큰·많은·최대·상위·순위·포함은 필수 검색어에서 제외 |
| 부서 하나·연도 하나의 세출 질문 | `department_overview`: 그 연도 본예산과 수록된 추경 회차 중 부서 머리말이 확인된 쪽을 모두 읽어(상한 80쪽, 중복 수록 시 쪽이 많은 문서 하나) 편성별 `department_total`, 금액순 상위 15개 `businesses`, 계산값 `latest_amounts`(`as_of` 표시), `largest_business`를 반환. 추경 명세서에는 변경 사업만 나오고 수록되지 않은 회차·스캔 쪽은 반영되지 않음. 다른 편성의 금액은 합산하지 않음 |
| "추경 포함" | "추경 포함·추경까지·추경도·합쳐·더해"는 본예산과 추경을 함께 조회. "추경 반영"은 추경만 조회 |
| 결산 근거 | 시 결산서는 질문이나 인자로 결산·집행액을 명시했을 때만 근거가 된다(`worker/policy.js`의 `sourceAllowed`). 결산을 묻지 않은 질문에는 예산편성(본예산·추경) 근거를 우선한다. 산하기관은 결산서가 유일한 세부 자료인 경우가 있어 기관을 명시한 질문에서는 결산서도 반환한다 |
| 금액 | 원문 단위와 환산값 구분. 상·하위 사업, 전체본·분할본 중복 합산 금지 |
| 분류 정보 | 부서 → 정책사업 → 단위사업 → 세부사업 → 편성목 코드/명 → 통계목 코드/명 |
| 원문 형식 | PDF 페이지와 인쇄 쪽수 구분. 엑셀은 시트·행·셀. HWP는 본문 블록 |

분류는 페이지 머리말과 확인한 사업명세서 서식의 들여쓰기를 이용해 추출한다. 한 페이지의 여러 사업 경로를 각각 반환한다. `layout_extracted`는 문서 구조 기반 추출이며, 모든 문서에 대해 사람이 검수한 정규화 사업 DB라는 뜻이 아니다. 미지원 서식은 `partial`과 빈 경로로 반환한다. `classification.note`와 원문을 보고 해당 금액에 대응하는 경로만 사용한다.

서버가 검색 범위를 결정하고 원문을 반환한다. 최종 문장 생성과 근거 충분성 판단은 연결한 ChatGPT가 수행하므로, 지침만으로 불필요한 호출을 완전히 차단할 수는 없다.
