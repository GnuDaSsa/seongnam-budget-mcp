# 조회·답변 규칙

정책 버전: 2026-11-08.1. 실행 원본: `worker/policy.js`.

| 질문 상황 | 적용 규칙 |
|---|---|
| 연도 미지정 | 2026년 검색. 답변에 “2026년 기준” 명시 |
| 연도 명시 | 해당 연도 우선. 다른 연도로 조용히 대체하지 않음 |
| 전체·역대 연도 | `year_scope=all`. ‘모든 예산’만 말하면 기본 연도 유지 |
| 작년·내년 | 정책 기준 2026년의 전년·다음 해. 실제 자료 유무 별도 확인 |
| 2~3개 연도 비교 | 서버가 연도별 검색을 수행. 최대 3개, 동일 문서·회계·사업 범위만 비교 |
| 총예산만 질문 | 2026년 본예산 총괄표를 직접 조회. 총액=일반+특별 검산 후 반환 |
| 편성목·통계목·세부사업 질문 | 문서 종류가 없으면 본예산 사업명세서를 우선 |
| 본예산·추경·결산 명시 | 필터 적용. 두 종류를 동시에 물으면 출처별 구분 |
| 최신 추경 | 수록된 해당 연도의 최종 회차. 완전한 최신 수집을 보장한다고 표현하지 않음 |
| 근거 충분 | 한 번의 `budget_research`로 답변. 상태 조회와 같은 뜻의 재검색 생략 |
| 근거 부족 | 표현을 좁힌 재검색 1회 또는 원문 조회. 없으면 확인 불가 |
| 금액 | 원문 단위와 환산값 구분. 상·하위 사업, 전체본·분할본 중복 합산 금지 |
| 분류 정보 | 부서 → 정책사업 → 단위사업 → 세부사업 → 편성목 코드/명 → 통계목 코드/명 |
| 원문 형식 | PDF 페이지와 인쇄 쪽수 구분. 엑셀은 시트·행·셀. HWP는 본문 블록 |

분류는 페이지 머리말과 확인한 사업명세서 서식의 들여쓰기를 이용해 추출한다. 한 페이지의 여러 사업 경로를 각각 반환한다. `layout_extracted`는 문서 구조 기반 추출이며, 모든 문서에 대해 사람이 검수한 정규화 사업 DB라는 뜻이 아니다. 미지원 서식은 `partial`과 빈 경로로 반환한다. `classification.note`와 원문을 보고 해당 금액에 대응하는 경로만 사용한다.

서버가 검색 범위를 결정하고 원문을 반환한다. 최종 문장 생성과 근거 충분성 판단은 연결한 ChatGPT가 수행하므로, 지침만으로 불필요한 호출을 완전히 차단할 수는 없다.
