# Stalled active work, cancellation and total-card validation

## Scope

Baseline: review-branch commit `e52315c2cbb44f3d8bc068b7347f77cca0783113`. Candidate adds a per-active-operation best-effort 30-second watchdog. Experiments use synthetic requests and local Wrangler 4.158.0 / workerd 2026-11-04, compatibility date 2026-11-07, local static assets. They do not deploy or establish hosted memory, CPU, cancellation or tail-latency behavior.

## Stalled work

When an active retrieval exceeds 30 seconds, its permit remains held: it is not cancelled or declared complete. Queued work is rejected with a retry message, and new **uncached** work fails fast before it can join the same in-flight promise. Fully cached evidence may still be served. When the actual long-running task settles, the watchdog clears for that task and the gate can recover. With multiple active tasks, completing a different task cannot clear a still-stalled task; tests cover multiple stalled tasks and rejection recovery. This is a fail-fast mitigation, not a hard task timeout, byte limit, isolate restart, or safe termination of a truly stuck task. A task that never settles may still monopolize the permit until external runtime recovery/restart. A CPU-bound infinite loop can prevent timers from firing. Direct page reads and other isolates are outside this gate.

A test-only Worker wrapper delayed one asset read by 35 seconds. In one paired local run (`stalled-workerd-probe-final.jsonl`), a distinct request submitted at 22 seconds completed after 13,262.55ms on baseline; on candidate it was rejected with the retry message after 7,710.61ms when the 30-second watchdog fired. The same-question request submitted at 31 seconds waited 4,259.52ms and then succeeded on baseline; on candidate it returned a retry error in 14.06ms while the original still ran. The original completed at roughly 35 seconds in both runs and a later unrelated query succeeded. Another initially queued request timed out after 15 seconds in both. This synthetic finite delay does not prove recovery from permanent hangs or production behavior.

Three paired runs of eight distinct concurrent questions (`stalled-regression-trials.jsonl`) had no errors; baseline and candidate evidence hashes matched 24/24 first responses and 24/24 repeats. First-batch wall-time medians were 1,268.57ms and 1,328.93ms respectively; repeats 21.46ms and 20.32ms. These small local samples do not establish a performance difference. A final one-pair Worker run after the number-format change also matched 8/8 first and 8/8 repeat evidence (`stalled-final-regression.jsonl`). A Node adapter check of 16 fixed presence/filter cases passed 16/16 on each and returned 16/16 identical evidence hashes; the seven-case smoke set, including the real 2026 total, passed 7/7 on each. These small, partly snapshot-derived checks do not establish corpus-wide precision or all-hit relevance.

## Client cancellation and shared work

A synthetic unit test aborts one consumer's local wait while two consumers share one Inflight result. It verifies the underlying task remains active, is not started twice or incorrectly released, and both underlying promises receive the same result after actual completion. In three paired local Worker cancellation runs (`stalled-cancellation-trials.jsonl`), each shared batch and mixed-query batch had four client aborts and four successful non-aborted calls; shared survivors had identical evidence and a later request succeeded. These observations do not prove disconnected work was removed from the server queue or that all production proxies propagate disconnects.

A separate test-only listener compared the current local compatibility settings with `enable_request_signal` explicitly added (`stalled-signal-probe.jsonl`). In both local trials the client observed AbortError, while the listener recorded 0 abort events and the handler completed. The local proxy may not propagate the disconnect; this does not prove the flag is unsupported by hosted Workers. The application does not enable the flag, pass client signals to the gate, cancel queued work on disconnect, or implement subscriber-aware cancellation. Do not cancel an underlying shared operation just because one subscriber leaves. Cloudflare's current compatibility guidance: https://developers.cloudflare.com/workers/configuration/compatibility-flags/ .

## Numeric accuracy

The total-card parser previously accepted partial/malformed tokens as integers: `1,00`, `100.5`, `100원`, and an amount on the next line all produced a card of 100 in synthetic cases. The candidate rejects all four, while accepting `1,000` with valid grouping (`total-token-before.jsonl`, `total-token-after.jsonl`). It requires same-line complete integer tokens with either no separators or correctly grouped thousands; the original unit, safe-integer and arithmetic checks remain. The real 2026 total fast-path regression still passes. Rejection is conservative and may fall back to search if a future source uses a different valid layout.

## Reproduction

Use the verified snapshot and local build setup in `workerd-report.md`. Prepare an isolated `work/stalled-baseline-src` from `git archive e52315c`, with the same ignored snapshot assets and dependencies, build it and copy verified token gzip files into its local `dist/client/semantic/`. For a finite stall test, `node experiments/prepare-stalled-probe.mjs`, then set `BASE_CONFIG` and `GATED_CONFIG` to the two generated `work/stalled-probe-*.json` files, `TRIALS=1`, and `PROBE_SCRIPT=experiments/workerd-stalled-probe.mjs` when running `node experiments/run-workerd-trials.mjs`. For the signal diagnostic, run `node experiments/prepare-signal-probe.mjs`, use its two configs and `PROBE_SCRIPT=experiments/workerd-signal-probe.mjs`. These wrappers are test-only and written under ignored paths. For three cancellation comparisons use the baseline build config and `PROBE_SCRIPT=experiments/workerd-cancellation-probe.mjs`; for eight-query comparisons omit `PROBE_SCRIPT`. Run `node experiments/total-token-probe.mjs`, `npm run test:unit` and `npm test`. Before rechecking snapshot hashes, restore the original compressed rank asset if build regenerated it.
